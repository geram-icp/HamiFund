# HamiFund ? P0 Value Engine Contract

## Purpose

Define how economic value is measured, calculated,
distributed and potentially reinvested.

## Valuation

Valuation produces a time-specific estimate of economic value.

Core fields:

- valuation_id
- target_ref
- valuation_method
- gross_value
- liabilities
- net_value
- currency
- valuation_at
- source_ref
- methodology_ref
- confidence_ref
- status
- version

Valuation must identify:

- what is being valued
- valuation methodology
- source
- valuation time
- currency

A valuation is a snapshot, not a permanent truth.

## Performance

Performance measures change in value over a defined period.

Core fields:

- performance_id
- target_ref
- period_start
- period_end
- opening_value
- closing_value
- cash_flow_ref
- gain_loss
- return_rate
- methodology_ref
- currency
- calculated_at
- version

Performance calculations must define treatment of:

- deposits
- withdrawals
- distributions
- fees
- expenses
- reinvestments

## Yield

Yield represents eligible economic return
generated by an investment or financial structure.

Core fields:

- yield_id
- source_ref
- target_ref
- gross_yield
- eligible_yield
- currency
- period_start
- period_end
- calculation_ref
- status
- version

Yield must distinguish:

- gross return
- costs
- fees
- losses
- adjustments
- eligible distributable amount

Economic activity does not automatically become
distributable yield.

## Distribution

Distribution allocates an approved eligible amount
according to an explicit policy.

Core fields:

- distribution_id
- source_ref
- policy_ref
- eligible_amount
- currency
- distribution_date
- allocation_method
- status
- approval_ref
- event_ref
- version

Lifecycle:

Calculated
? Reviewed
? Approved
? Posted
? Reconciled

Distribution requires:

- eligible yield
- applicable policy
- authorization
- accounting treatment
- recipient allocation rules

## Reinvestment

Reinvestment converts an eligible distribution
into a new financial allocation.

Core fields:

- reinvestment_id
- source_distribution_ref
- target_ref
- amount
- currency
- policy_ref
- status
- event_ref
- idempotency_key
- version

Lifecycle:

Proposed
? Authorized
? Allocated
? Posted
? Reconciled

## Value Flow

Economic Activity
? Revenue / Return
? Valuation
? Performance
? Eligible Yield
? Distribution Policy
? Distribution
? Reinvestment OR Redemption

## NAV Relationship

NAV may use:

Asset Values
+
Cash
-
Liabilities
-
Applicable Adjustments

The exact methodology must be defined by the
relevant fund or portfolio policy.

## Valuation Sources

Possible sources:

- internal valuation model
- approved external valuation
- oracle reference
- market data
- verified project data
- financial statements

Every valuation must retain its source reference.

## Valuation Uncertainty

Where appropriate, valuation may include:

- methodology
- confidence indicator
- source quality
- valuation range
- stale-data indicator

Uncertainty must not be silently represented
as exact market value.

## Fees & Expenses

Value calculations must support:

- management fees
- performance fees
- transaction costs
- operating expenses
- settlement costs
- other approved expenses

Fees must be represented explicitly.

## Negative Performance

Negative performance must remain representable.

The system must not manufacture yield merely to
produce a positive distribution.

## Distribution Safety

A distribution cannot exceed the amount that is
eligible under the applicable policy and accounting rules.

## Reinvestment Safety

Reinvestment requires:

- valid source distribution
- eligible amount
- authorization
- target validation
- risk/policy checks
- idempotency
- ledger evidence

## Value Engine Invariants

1. Valuation is a snapshot.
2. Performance is period-specific.
3. Yield is not automatically distribution.
4. Distribution requires policy and authorization.
5. Reinvestment creates new financial evidence.
6. Negative performance is preserved.
7. Valuation source is explicit.
8. Currency is explicit.
9. Fees and expenses are explicit.
10. Value calculations must be reproducible from recorded inputs.
